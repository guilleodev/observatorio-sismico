## 2. Riesgo principal encontrado
**El PC se suspenderá solo.** Con el plan actual: **suspender tras 3 600 s (1 h) de inactividad con alimentación y 600 s (10 min) con batería**; hibernar «nunca»; apagar pantalla a 3 600 s (CA) y 180 s (batería). Al suspenderse, Docker, la API, el consumidor, el productor y ngrok dejan de funcionar: la web mostrará «Sin conexión» y se perderán consultas a USGS (huecos de ingesta que se recuperan con `recuperar --listar/--simular`; precedente: la parada de ≈ 19,6 h y el hueco #475). ## 4. Recomendaciones (**no aplicadas**: son cambios de configuración del sistema que decide la persona estudiante)
1. Mantener el equipo **enchufado** durante la ventana.
2. Configuración → Sistema → Alimentación: **Suspender: nunca** (con alimentación); si es portátil, acción al cerrar la tapa «No hacer nada»; la pantalla sí puede apagarse. Equivalente por consola: `powercfg /change standby-timeout-ac 0` (la persona estudiante decide si lo aplica).
3. **Pausar las actualizaciones de Windows** durante la ventana (Configuración → Windows Update → Pausar actualizaciones) y no reiniciar el equipo.
4. **Iniciar sesión automáticamente** o comprobar que tras un reinicio Docker Desktop vuelve y los cinco servicios quedan `healthy`; abrir ngrok a mano con el comando de `checklist-ventana-evaluacion.md`.
5. Cerrar `npm run start:local` y el navegador con pestañas de F7 abiertas sin necesidad antes de abrir el túnel.
6. Leer el contador de ngrok (Usage) antes de la ventana.
7. **Regla durante la ventana**: no cambiar código ni servicios, no ejecutar scripts que paren o recreen contenedores y no activar mantenimiento salvo incidencia.
