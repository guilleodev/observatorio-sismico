## Reglas transversales (aplican a todas las tareas)

- No hacer commits ni push: el commit de cierre **`[F5]`** lo realiza manualmente la persona estudiante desde VS Code.
- No marcar una verificación como superada sin ejecutarla; guardar la salida real en `docs/evidencias/f5/`. Tiempos y recuentos se anotan tal como se observan; los
  umbrales de rendimiento están **pendientes de medición** (SC-010): se proponen tras medir y los confirma la persona estudiante.
- **Datos**: no insertar eventos ficticios ni dañados en tablas definitivas (`live.*`, `geo.*`, `historico.*`); las pruebas con PostgreSQL usan una transacción que se
  revierte o una base temporal. Los ensayos de fallo (base caída, ingesta antigua, truncado forzado) usan **una API y una base temporales**: nunca se para PostgreSQL,
  el productor ni el consumidor reales. **No borrar volúmenes ni datos** (sin `down -v`, sin recrear Kafka ni PostgreSQL); una operación destructiva se consulta antes.
- **Despliegue**: solo se reconstruye `api` (`docker compose up -d --build --no-deps api`); antes, comprobar los cinco servicios `healthy`, lag 0 y reconciliación vacía.
  `INGESTA_PUBLICAR=true` sigue en el `.env` local.
- No modificar `docs/referencias/`, `specs/001-…`, `specs/002-…`, `specs/003-…`, `frontend/public/datos/paises.geojson` ni `terremotos-demo.geojson`. El contrato solo
  se amplía de forma aditiva. Del frontend solo se tocan `frontend/src/app/`, `frontend/tests/` y, sin secretos, `frontend/public/config.json` (DF1).
- Al cerrar cada paso: resumir archivos, explicar el código por bloques, justificar decisiones y proponer una pregunta de defensa (`CLAUDE.md`).
- Sin dependencias nuevas salvo aprobación expresa (DF2, DF5). Pruebas de backend en `backend/tests/unit/`; del frontend en `frontend/tests/`.
- Terminología: «estado actual» = `live.evento_actual` sin retirados; «sin país» = `geo_resultado = 'sin_pais'`; `*_at` = `timestamptz`; fechas del contrato en ms UTC.
